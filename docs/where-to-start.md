# С чего начать

Михаил, Daniel: репозиторий [portfolio-event-radar](https://github.com/mawarzd/portfolio-event-radar) уже держит концепцию, а первый рабочий вызов T-Invest MCP упирается в TLS. Сертификат `*.tbank.ru` выпущен Russian Trusted Sub CA Минцифры. Пока этих корней нет в доверенных, клиент видит обрыв «self-signed certificate in certificate chain» и до портфеля, котировок и лимитов не доходит.

## Что отдаёт MCP

[T-Invest MCP](https://developer.tbank.ru/invest/mcp) — удалённый сервер по Streamable HTTP. Боевой адрес `https://invest-public-api.tbank.ru/mcp`, песочница `https://sandbox-invest-public-api.tbank.ru/mcp`. Авторизация та же, что у T-Invest API: заголовок `Authorization: Bearer <токен>`. Токен выпускается в [настройках Т-Инвестиций](https://www.tbank.ru/invest/settings/), показывается один раз, живёт три месяца с последнего использования и должен быть применён в течение семи дней. Виды: только чтение, полный доступ, переводы, токен на один счёт и отдельный токен песочницы. Для [песочницы](https://developer.tbank.ru/invest/intro/developer/sandbox/) нужен её адрес и её токен; боевой токен туда не подходит.

Инструменты повторяют публичное API и добавляют то, чего в голом справочнике методов нет. Официальная страница группирует их так:

| Группа | Что можно спросить | Зачем радару |
|---|---|---|
| Счёт и портфель | Позиции, свободные деньги, оценка, доходность, история операций | Доля бумаги в скоринге и текст «почему это важно именно этому портфелю» |
| Рынок | Стакан, свечи, последние сделки, индикаторы, торговый календарь, статусы | Срочность и контекст цены рядом с событием |
| Справочник | Поиск и параметры акций, облигаций, фондов, фьючерсов, валют | Привязка события к ISIN/FIGI |
| Выплаты | Дивиденды, купоны, НКД, календарь облигаций | Купон, оферта и погашение приходят уже структурированными, без LLM |
| Аналитика | Новости, сентимент, фундаментал, сигналы, сделки инсайдеров | Дополнительный источник к e-disclosure и RSS, со ссылкой в карточке |
| Торговля и переводы | Рыночные и лимитные заявки, стоп, тейк, трейлинг, отмена и замена, пополнение и перевод между своими счетами | Только исполнитель и только после кнопки «Подтвердить» |

Имена отдельных tools банк на странице не публикует: их список появляется в клиенте после успешного подключения. В [разборе от команды публичного API](https://habr.com/ru/companies/tbank/articles/1086714/) для портфеля указан вызов `invest_get_portfolio` с `responseView: FULL` — позиции и средняя цена покупки.

Лимиты — те же, что у [T-Invest API](https://developer.tbank.ru/invest/intro/intro/limits), и они общие на все счета пользователя. Для радара важны такие потолки unary-запросов: котировки 600 в минуту, операции 200, счета 100, песочница 200, справочники инструментов 200, а методы `Bonds` / `Shares` / `Options` / `Futures` / `Etfs` / `GetAssets` вместе только 15 в минуту. Стрим котировок — 32 соединения и 300 одновременных подписок на свечи, стакан и ленту сделок. С одного IP банк рекомендует держаться в пределах 1000 запросов в минуту. Минутные свечи по всему портфелю в этот бюджет не входят: массовый сбор в архитектуре уже отдан прямому API и расписанию, а MCP — точечным вызовам агента.

## Как это ложится на текущий репозиторий

Сейчас в репозитории нет процесса, который можно запустить. На `main` лежат README, `docs/architecture.md`, `docs/data.md`, `docs/experiment.md`, контракт классификатора `schemas/event_classification.schema.json` и схема PostgreSQL `db/schema.sql`. Это согласованная архитектура MVP, а не работающий бот.

В этой архитектуре MCP уже стоит на своём месте. Коллекторы по расписанию ходят в T-Invest API за календарём и свечами. Агент через MCP только читает: актуальная позиция, параметры бумаги, котировка. Заявку отправляет отдельный исполнитель и только по черновику, который пользователь подтвердил кнопкой. Токен только на чтение совпадает с циклом агента; полный доступ нужен одному исполнителю и на отдельном токене. Песочница для первой проверки подходит: те же инструменты, виртуальные счета, без боевых денег. В песочнице не считаются часть показателей портфеля, счета живут три месяца, пополнение только в рублях и не больше 30 млн.

И API коллекторов, и MCP агента сидят на хостах с одной цепочкой Минцифры. Сертификат нужен обоим контурам. В Docker он нужен внутри образа: хранилище хоста в контейнер не попадает. Python (`requests`, `httpx`) берёт bundle certifi и системные корни сам не видит, поэтому рядом с установкой в ОС нужны `SSL_CERT_FILE` и `REQUESTS_CA_BUNDLE`.

## Первый шаг

Поставить в доверенные оба сертификата НУЦ Минцифры — корневой Russian Trusted Root CA и промежуточный Russian Trusted Sub CA — в то окружение, из которого пойдут вызовы. Одного корневого мало: без промежуточного остаётся `unable to get local issuer certificate`. Файлы скачиваются со [страницы Госуслуг](https://www.gosuslugi.ru/crt); прямые ссылки, которыми пользуется [инструкция Т-Банка](https://developer.tbank.ru/docs/tls-settings):

- https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer
- https://gu-st.ru/content/Other/doc/russian_trusted_sub_ca.cer

Оба файла уже в PEM. Отпечатки SHA-256: корень `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31` (до 27 февраля 2032), промежуточный `BB:BD:E2:10:3E:79:0B:99:9E:C6:2B:D0:3C:F6:25:A5:A2:E7:C3:16:E1:0A:FE:6A:49:0E:ED:EA:D8:B3:FD:9B` (до 6 марта 2027, к этой дате файлы нужно скачать заново).

На Debian/Ubuntu:

```bash
sudo cp russian_trusted_root_ca.cer /usr/local/share/ca-certificates/russian_trusted_root_ca.crt
sudo cp russian_trusted_sub_ca.cer /usr/local/share/ca-certificates/russian_trusted_sub_ca.crt
sudo update-ca-certificates
export SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt
export REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt
curl -sI https://sandbox-invest-public-api.tbank.ru/mcp
```

Успех — HTTP 401. Так сервер говорит, что цепочка доверена и не хватает токена. Тот же ответ у боевого `https://invest-public-api.tbank.ru/mcp`.

Проверено 21 ноября 2026, 11:12 МСК: до установки `curl` обрывался на сертификате (`ssl_verify_result` 19), после установки обоих CA песочница и боевой адрес вернули `401`, `ssl_verify_result` 0. Сертификат сервера выпущен Russian Trusted Sub CA на `*.tbank.ru`, организация TBank.

В образ, где будут коллекторы и агент, те же два файла кладутся на этапе сборки, затем `update-ca-certificates` и те же две переменные. Иначе бот в Docker снова получит ошибку TLS, хотя на ноутбуке `curl` уже отвечает 401.
