# Данные

## Источники

| # | Данные | Источник | Формат | Обновление | Ограничения |
|---|---|---|---|---|---|
| 1 | Портфель, позиции, цены | T-Invest MCP, токен инвестора только на чтение | JSON | Перед сборкой сводки | Только с согласия инвестора; MCP сейчас для собственного использования клиентом-физлицом |
| 2 | Эмитенты и их выпуски | T-Invest API (`GetAssetBy`, `Bonds`), MOEX ISS | JSON | Раз в сутки | Связь «ИНН — актив — выпуски» нужно проверить на выборке |
| 3 | Оферты, погашения, амортизации, дата дефолта | T-Invest API (`GetBondEvents`) | JSON | Раз в сутки | У события оферты нет дат начала и конца приёма заявок |
| 4 | Окна приёма заявок на оферту | Календарь облигаций MOEX ISS | JSON | Раз в сутки | Условия использования данных биржи для продукта нужно проверить |
| 5 | Сообщения эмитентов | e-disclosure.ru | HTML / PDF | Каждые 10–15 минут | Нет единого удобного API, часть сообщений в PDF; условия использования проверить |
| 6 | Релизы рейтинговых агентств | Сайты АКРА, «Эксперт РА», НКР, НРА | HTML | Каждый час | У каждого агентства свой формат страницы |
| 7 | Новости о выплатах эмитента по другим инструментам и его заявлениях | Новостные ленты, группа «Аналитика» в T-Invest MCP | HTML / текст | Каждые 10–15 минут | Дубли одной новости из разных лент; привязка к эмитенту по названию и ИНН |
| 8 | Отметки инвесторов | Своя БД | Таблицы | Постоянно | На старте их нет |

Во второй очереди: нарушение ковенант в отчётности (первым — на проверке 6 эмитентов это дало запас у «Монополии»), сведения о блокировке счетов, реестр заявлений о банкротстве.

## Справочник эмитентов

Каждая запись привязывается к компании по ИНН. Справочник связывает ИНН эмитента с активом в T-Invest API и всеми выпусками этого актива. Так публикация по одному выпуску попадает в сводку держателей остальных выпусков того же эмитента.

Связанные компании — поручитель, дочерняя, материнская — модель указывает по тексту. В сводку инвестора запись о связанной компании попадает, только если ИНН этой компании есть в справочнике как эмитент или поручитель по его выпускам.

## Разметка

Готового датасета нет, размечаем сами: 300 текстов по эмитентам выборки ретро-прогона, два разметчика независимо, расхождения разбираем вместе. Разметка служит для оценки извлечения и сравнения с правилами по ключевым словам.

Для каждого текста разметчик заполняет те же поля, что и модель:

| Поле | Что указывать |
|---|---|
| Компания и ИНН | О ком сообщение. Если в тексте несколько компаний — та, о чьём событии речь |
| Связанные компании | Поручитель, дочерняя, материнская компания, если сообщение о них, с указанием связи |
| Что произошло | Одна строка своими словами, только факт, без оценки |
| Тип события | Одно значение из списка ниже |
| Касается выплат / рейтинга / условий | Три отметки «да / нет» |
| Дата события | Дата из текста, не дата публикации |
| Цитата | Фрагмент текста, на котором держится запись, дословно |

Типы событий:

| Тип | Когда ставить |
|---|---|
| `coupon_rate_set` | Установлена ставка купона на следующие периоды |
| `coupon_payment` | Купон выплачен в срок |
| `payment_delay` | Выплата по любому инструменту не проведена в срок или проведена частично, включая «народные» облигации и ЦФА |
| `default_declared` | Биржа, эмитент или представитель владельцев объявили дефолт |
| `put_offer` | Объявлена или проведена оферта по требованию владельцев |
| `call_offer` | Эмитент объявил досрочное погашение по своему решению |
| `redemption` | Погашение выпуска |
| `amortization` | Частичное погашение номинала |
| `bondholders_meeting` | Собрание владельцев облигаций — с повесткой в строке «что произошло» |
| `issue_terms_change` | Изменены условия выпуска: сроки, ставка, порядок выплат |
| `restructuring` | Объявлена реструктуризация долга |
| `rating_upgrade` / `rating_downgrade` / `rating_affirmed` / `rating_withdrawn` | Рейтинговое действие агентства |
| `rating_watch` | Рейтинг помещён «под наблюдение» или изменён прогноз |
| `bankruptcy_filing` | Заявление или намерение подать заявление о банкротстве |
| `reporting` | Публикация или перенос публикации отчётности, смена аудитора |
| `asset_deal` | Сделка с ключевыми активами: продажа, залог, крупный заём |
| `management_change` | Смена руководителя или контроля |
| `account_block` | Приостановлены операции по счетам эмитента, например решением налоговой |
| `other` | Всё остальное |

Правила разметки:

- отмечаем факт, а не своё мнение о нём: «рейтинг понижен до ruC», а не «у эмитента серьёзные проблемы»;
- в строке «что произошло» нет слов «плохо», «опасно», «стоит продать» и любых оценок;
- если текст о нескольких событиях, размечаем главное, остальные — отдельными записями;
- если компанию нельзя определить уверенно, ставим отметку «не уверен», такие тексты разбираем вдвоём.

## Выборка для ретро-прогона

- 20–30 эмитентов с первым техническим дефолтом или дефолтом в 2025–2026 годах, у которых были биржевые выпуски, доступные частным инвесторам;
- столько же эмитентов того же сегмента без кредитных событий за тот же период;
- по каждому — тексты за 12 месяцев до первой невыплаты; для контрольных — за тот же календарный период.

Первым разбираем «ЕвроТранс»: хронология с 19 марта по 5 августа 2026 года уже собрана по публикациям.

## Персональные данные

- Портфель читается только с явного согласия инвестора и только в объёме, нужном для сводки.
- Модель развёрнута на своей инфраструктуре и видит только публичные тексты. Портфель в модель не передаётся.
- Для ретро-прогона используются модельные портфели, реальные данные клиентов не нужны.
